# Подбор кредитора (MVP)

Программа для кредитного брокера на Windows-ПК:

1. **Кредиторы** — база кредиторов и их требований к заёмщику (юрлица и ИП).
2. **Клиенты** — анкета клиента, автозаполнение и проверка по ИНН в бесплатных открытых источниках.
3. **Подбор** — список кредиторов: «подходят», «условно» (что уточнить), «не подходят» (почему),
   стоп-факторы и готовое резюме для копирования.
4. **Сайты кредиторов** — отслеживание изменений на страницах с условиями.

Нейросети не используются. Все данные хранятся локально в папке `data` рядом с программой.
Интернет нужен только для проверки по ИНН и проверки сайтов кредиторов.

## Установка

**Вариант 1 — готовый .exe (рекомендуется).**
GitHub → вкладка *Actions* → последний запуск *kredit-broker* → *Artifacts* → `KreditBroker-windows`.
Распакуйте `KreditBroker.exe` в отдельную папку (например, `C:\KreditBroker`) и запустите.
Откроется браузер с программой. Чёрное окно не закрывайте: это и есть программа.

Windows SmartFilter может предупредить о неизвестной программе: «Подробнее» → «Выполнить в любом случае».

**Вариант 2 — из исходников.** Установите Python 3.11+ с python.org (галочка *Add to PATH*),
затем двойной щелчок по `start.bat`. Собрать .exe самостоятельно можно через `build_exe.bat`.

## Как работать

1. **Кредиторы → Добавить.** Заполните карточку и только те требования, которые есть у кредитора.
   Пустое требование не проверяется. К карточке можно приложить исходники: скриншоты, PDF, Word.
   - **Мягкое** требование: несоответствие не исключает кредитора, а переводит его в «условно».
   - У кредитора несколько продуктов → каждый отдельной карточкой (кнопка «Копия»).
2. **Клиенты → Новый клиент.** Введите ИНН → «Проверить и заполнить». Программа обратится к
   ЕГРЮЛ/ЕГРИП, ГИР БО (выручка, прибыль) и ЕФРСБ (банкротство) и заполнит анкету.
   Остальное дополните по интервью. Пустое поле = «неизвестно».
3. **«Сохранить и подобрать кредиторов».** Результат:
   - **Стоп-факторы:** банкротство, ликвидация, а также требование, которое не проходит ни у одного
     кредитора (например, срок работы 1 мес. при минимуме 3 мес. у всех).
   - **Подходят:** все требования выполнены. Сортировка по проценту совпадения, затем по вознаграждению.
   - **Условно:** не хватает данных или не выполнены только мягкие требования. Видно, что уточнить.
   - **Не подходят:** с причинами.
   - **Резюме:** кнопка «Скопировать» (для CRM или мессенджера), «Печать / PDF».
4. **Настройки → Дополнительные критерии.** Любые свои требования (да/нет или число). Они появятся
   и в анкете клиента, и в карточке кредитора.
5. **Перенос коллеге:** Настройки → «Выгрузить кредиторов» → коллега делает «Загрузить» у себя.

## Источники проверки

| Источник | Что даёт | Режим |
| --- | --- | --- |
| ЕГРЮЛ/ЕГРИП (egrul.nalog.ru) | название, форма, дата регистрации → срок работы, регион, руководитель, ликвидация | автоматически |
| ГИР БО (bo.nalog.ru) | ОКВЭД, выручка и чистая прибыль за последний год (только юрлица) | автоматически |
| ЕФРСБ (bankrot.fedresurs.ru) | банкротство | автоматически |
| Прозрачный бизнес, картотека арбитражных дел, ФССП, Rusprofile, Checko, реестр МСП, реестр недобросовестных поставщиков | долги по налогам, суды, исполнительные производства, РНП | ссылки для ручной проверки (на сайтах капча) |

Сайты госисточников иногда меняют формат. Если источник перестал отвечать, в отчёте будет причина,
остальные проверки при этом продолжат работать.

## Резервная копия

Все данные лежат в папке `data` рядом с программой. Для бэкапа скопируйте её целиком.

## Для разработчика

```bash
pip install -r requirements.txt pytest
python -m pytest -q      # тесты
python run.py            # запуск, http://127.0.0.1:8765
```

Структура:
- `broker/criteria.py`: поля анкеты, требования кредиторов, движок подбора. Новый критерий =
  одна строка в `CLIENT_FIELDS` и одна в `LENDER_CRITERIA`.
- `broker/checks.py`: источники проверки по ИНН.
- `broker/monitor.py`: отслеживание страниц кредиторов.
- `broker/db.py`: хранилище SQLite.
- `broker/web.py`, `broker/templates`: интерфейс.
